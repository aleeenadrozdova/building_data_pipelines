# HW2 — Объективная система оценки преподавателей (университет)

**Постановка:** создать объективную систему оценки преподавателей студентами и руководством
университета. Оценка должна быть **выведена из базовых принципов** и **максимально прозрачна
для преподавателя** — он должен понимать, за что и как сформирована его оценка (за что «срезали»).

## Базовые принципы (из чего выводим оценку)

1. **Объективность** — оценка строится из фактов (опросы, данные о результатах), а не из
   личного мнения конкретного менеджера.
2. **Прозрачность** — каждая компонента оценки объяснима и воспроизводима: у преподавателя
   есть формула, свои значения по каждой компоненте и история.
3. **Многосторонность** — учитываются разные перспективы: студенты, коллеги/руководство,
   фактические результаты процесса обучения.
4. **Сопоставимость** — оценка нормируется по типу курса/кафедре, чтобы сравнивать только
   сопоставимое.
5. **Защита от манипуляций и предвзятости** — устойчива к «договорным» оценкам, аномальным
   выбросам, малому числу ответов.

Из них выводится составная модель: `Оценка = f(Оценка студентов, Оценка руководства/коллег,
Результаты обучения)` с весами и публичной формулой.

## 1. User Stories (для данных)

**US-1. Преподаватель (понимает и может улучшить свою оценку)**
> «Как преподаватель, я хочу видеть свою агрегированную оценку по компонентам (студенты,
> руководство, результаты) и конкретные значения метрик в разрезе каждого курса и семестра,
> чтобы понимать, что именно снизило оценку и на чём сфокусироваться».

**US-2. Студент (участвует в оценке, видит её эффект)**
> «Как студент, я хочу честно и конфиденциально оценивать преподавателей и курсы в конце
> семестра по понятной анкете, и видеть, что эти данные влияют на программу (обратная связь
> публикуется по правилам)».

**US-3. Руководство (принимает решения и управляет качеством)**
> «Как заведующий кафедрой/деканат, я хочу получать агрегированный рейтинг преподавателей по
> кафедрам с drill-down до курса и семестра, чтобы обоснованно решать о нагрузке, премировании,
> наставничестве и развитии программы».

**US-4. Аналитик качества образования (объясняет и проверяет)**
> «Как аналитик, я хочу видеть raw-данные опросов (без ПДн отвечающих), историю метрик и
> причины их изменения, чтобы любому преподавателю объяснить, откуда взялась оценка, и
> ловить аномалии (накрутки, «скамейки»)».

## 2. Data Product Canvas (сокращённый)

| Блок | Содержание |
|---|---|
| **Название продукта** | `teaching_quality_score` — оценка качества преподавания |
| **Потребители** | Преподаватель (личный кабинет), студент (анкета/обратная связь), руководство (рейтинги), аналитик качества |
| **Источники данных** | Анкеты студентов (survey responses), оценки руководства/коллег, данные о курсе (нагрузка, число студентов, посещаемость), результаты обучения (экзамены/сдачи, успеваемость курса) |
| **Транформации** | Нормализация по типу курса, очистка/дедуп ответов, работа с выбросами, веса компонент, агрегация по семестру/кафедре |
| **Выходные данные** | Витрина `teacher_score` (id, семестр, курс, компоненты, итог, raw-признаки); кабинет; рейтинги |
| **Схема доставки** | Семестровый батч (после закрытия опросов) + оперативная доля по части курсов |
| **Владелец** | Учебный офис / департамент качества образования |
| **Метрики качества данных + SLA** | см. раздел 3 |
| **Периодичность** | Ежесеместрово; контроль свежести в окне приёма ответов |

## 3. Ключевые метрики качества данных + SLA

**(A) Свежесть (Freshness)**
- **Метрика:** время между закрытием опросов по курсу и публикацией обновлённой оценки
  `teacher_score` за семестр.
- **SLA:** оценка по семестру публикуется **не позднее 7 календарных дней** после закрытия
  приём анкет; `p95` ≤ 7 дней.

**(B) Полнота покрытия (Completeness)**
- **Метрика:** доля курсов/преподавателей, у которых есть полный набор компонент (студенты +
  руководство + результаты), без пропущенных.
- **SLA:** **≥ 95%** курсов имеют полную оценку; иначе — публикуется оценка с пометкой о
  неполноте и укороченным весом непокрытой компоненты.

**(C) Достоверность/валидность ответов (Validity)**
- **Метрика:** доля ответов, прошедших валидацию (уникальный студент, не аномальный выброс,
  корректные границы шкалы; «договорные»/свал-ответы фильтруются).
- **SLA:** **≥ 95%** ответов валидны; при доле < 80% на курс — оценка по этому курсу
  помечается как недостоверная и не включается в общий рейтинг.

**(D) Согласованность с источником (Reconciliation)**
- **Метрика:** расхождение числа валидных ответов в витрине vs контрольная сводка из системы
  опросов за тот же курс/семестр.
- **SLA:** расхождение **≤ 0 добавленных/потерянных ответов** (допуск на округление 0.1%);
  иначе — блокировка публикации и пересчёт.

## Прозрачность для преподавателя (как выполнено)

В личном кабинете преподаватель видит:
- **формулу**: `Score = 0.5·Students + 0.3·PeersДManagement + 0.2·Outcomes`,
- **каждую компоненту** с метриками и её долей ответов,
- **нормировку** относительно кафедры/типа курса (чтобы понимать, почему сравнивается именно так),
- **историю** по семестрам и **версии правил** (что менялось в весах/методике).

Так выполняется принцип прозрачности: любому объяснимому срезу есть обоснование в данных,
а «снижение» оценки всегда конкретизировано компонентой и показателем.
