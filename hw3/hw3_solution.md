# HW3 — Тест производительности форматов (RetailFlow)

**Цель:** сравнить Parquet, Avro, CSV, JSON на датасете ~10 ГБ событий покупок:
объём хранения, время записи, время чтения (full scan, выборка, агрегация).

**Как воспроизвести:** см. `RUN_ME.md` (генерация данных `gen_data.py`, замеры `bench_write.py` / `bench_read.py`).

---

## 1. Датасет

Синтетические события покупок (e-commerce), партиционированы по `event_type` (view/cart/purchase/refund).
Колонки: `event_id, event_type, user_id, session_id, product_id, seller_id, category_id, price, quantity, city_id, device, is_promo, ts`.

- **Объём исходника (Parquet):** ~3.9 ГБ
- **Окружение:** Apache Spark 4.2.0, локальный режим (Mac)

---

## 2. Результаты

### Т1 — Запись (объём хранения, время записи)

Исходник: `hw3/data/source` (Parquet, ~3.9 ГБ).

| Формат | Объём хранения, МБ | Время записи, сек | Меньше/больше исходника |
|---|---|---|---|
| Parquet (snappy) | 3902.49 | 52.31 | ≈ исходнику (это и есть Parquet) |
| Avro | 4692.70 | 32.67 | в ~1.2 раза больше Parquet |
| CSV (tab) | 12171.95 | 61.49 | в ~3.1 раза больше Parquet |
| JSON | 29472.20 | 28.61 | в ~7.5 раза больше Parquet |

### Т1-комментарий (по фактическому прогону)

- **Объём:** Parquet самый компактный (~3.9 ГБ), Avro ~на 20% больше, CSV в ~3 раза больше,
  JSON — сразу в **~7.5 раза** больше Parquet (дублирование ключей на строку + текст без сжатия).
- **Скорость записи:** Avro и JSON пишутся быстрее всех (мало/нет сжатия), CSV — самый медленный
  (текст, много байт на диск); Parquet — посерединке (платит за сжатие и колоночную упаковку).
- Ключевой вывод: дешёвая запись Avro/JSON «окупается» только там, где размер диска не важен;
  для хранения 30 дневного потока JSON дал бы в 7.5 раза больший объём того же Parquet.

### Т2 — Чтение (сек, минимум из N повторов)

| Формат | Full scan (count) | Выборка (filter+select) | Агрегация (groupBy sum) |
|---|---|---|---|
| Parquet | **0.141** | **0.150** | **0.855** |
| Avro | 6.225 | 6.877 | 6.645 |
| CSV | 7.093 | 14.608 | 17.187 |
| JSON | 25.892 | 28.687 | 33.515 |

### Т2-комментарий (по фактическому прогону)

- **Parquet в разы быстрее по всему спектру:**
  - full scan — мгновенный (0.14 с): Parquet считает count из метаданных файла, без чтения данных;
  - выборка — колоночное чтение + predicate pushdown (читаются только нужные колонки/партиции):
    **в ~46 раз** быстрее, чем CSV (0.150 vs 7.09 → с поправкой на метаданные), и в ~190 раз быстрее JSON (0.150 vs 28.7);
  - агрегация — 0.86 с против 6.6 (Avro), 17.2 (CSV), 33.5 (JSON): читаются только 3 колонки
    (`category_id`, `price`, `quantity`) из 12.
- **Avro** (строкный формат) читается с той же скоростью примерно для всех операций (~6–7 с) —
  нет ни метаданных count, ни pushdown, нечего «отсекать».
- **CSV/JSON** — текст: распарсивание строк, отсутствие pushdown, JSON ещё и огромный по объёму
  → самый медленный.
- `full_scan` Parquet ≈ 0 — за счёт row-count в footer (это честный факт формата: count дешёвый).

## 3. Выводы по фактическим замерам

**Объём хранения (подтверждено Т1):**
- Parquet — самый компактный (колоночное хранение + snappy; словарное сжатие повторяющихся значений).
  В нашем прогоне CSV больше в **3.1 раза**, JSON — в **7.5 раза**.
- Avro — строкное хранение, на ~20% больше Parquet (рядовые колонки без словарного сжатия).

**Скорость записи (Т1):**
- Быстро пишут Avro (32.7 с) и JSON (28.6 с) — у них меньше/нет сжатия.
- CSV — медленнее всех (61.5 с, много «сырого» текста на диск), Parquet — 52.3 с (платит за сжатие).

**Скорость чтения (Т2, самый показательный блок):**
- **Parquet быстрее всех по всем операциям** (0.14/0.15/0.86 с):
  count из метаданных + колоночное чтение + predicate pushdown + чтение только нужных колонок.
- Avro — стабильно ~6–7 с (строкный формат, ничего не «отсекается»).
- CSV — 7–17 с (текст, без pushdown), JSON — 26–34 с (огромный объём + парсинг).

## 4. Итог / рекомендации для RetailFlow (по фактическим данным)

- **Аналитический слой (silver/gold, агрегации и фильтры): Parquet.** В замере он
  в **20–40× быстрее** конкурентов на выборке/агрегации и в ~8 раз компактнее JSON.
- **Потоковая сериализация между сервисами / в Kafka: Avro** — компактность близка к Parquet,
  а строкная запись (32.7 с — дешевле всего среди «разумных» форматов) и схема-совместимость
  удобнее для записи в топики ещё до партиционирования.
- **CSV/JSON — только ad-hoc/экспорт и приём «сырых» данных из внешних систем**: JSON удобен
  на входе (легко парсить произвольную вложенность), но на хранение его перекодируют в Parquet.
- **Практический вывод для дата-платформы:** приём сырьё → перекодировка в Parquet до анализа;
  Avro — внутри потокового контура; объём хранения JSON в 7.5× — это прямой рост стоимости
  хранения/сети без выигрыша в скорости.
